# Porting guide — DC prototype → React

You are porting slices of a design-tool prototype (`.dc.html`) into React function components for a Vite + React app. **Goal: pixel-faithful reproduction of the prototype.** Match every style value exactly.

## The transform rules (dc markup → JSX)

| Prototype (dc) | React |
|---|---|
| `style="a:b;c:d"` (HTML string) | `style={{ a: 'b', c: 'd' }}` — **camelCase keys**, values are **strings copied verbatim, keep units** (`'16px'`, `'999px'`). Keep shorthands whole: `font:'700 13px ...'`, `background:'linear-gradient(...)'`, `boxShadow:'...'`, `transform:'...'`. |
| `{{ someVar }}` | `{someVar}` — comes from `useStore()` (see field list). |
| `onClick="{{ fn }}"` | `onClick={fn}` |
| `onClick="{{ handlerTakingEvent }}"` with `data-id`/`data-act`/`data-k`/`data-v`/`data-f`/`data-d` | Call the store action with the datum directly, e.g. `onClick={() => guestAct(g.id, 'send')}`, `onChange={(e) => onEventField(f.k, e.currentTarget.value)}`. Do NOT rely on `data-*`. |
| `style-hover="a:b"` | wrap element in `<Hover as="button" style={{...}} hover={{ a:'b' }}>` from `../components/ui.jsx`. For `<a>` use `as="a"`. |
| `style-focus="..."` on input/textarea | use `<FocusInput as="input" style={{...}} focus={{...}} .../>` from `../components/ui.jsx`. |
| `<sc-if value="{{ cond }}">…</sc-if>` | `{cond && (<>…</>)}` |
| `<sc-for list="{{ arr }}" as="x">…</sc-for>` | `{arr.map((x) => (<Fragment key={x.id}>…</Fragment>))}` — always set a `key`. |
| `value="{{ x }}" onChange="{{ h }}"` on input | controlled: `value={x} onChange={(e) => h(e.currentTarget.value)}` (the store setters take the value directly, not the event). |
| `href="#/"` / `href="#/registry"` / `href="#/admin"` | React Router: `import { Link } from 'react-router'` → `<Link to="/">`, `<Link to="/registry">`, `<Link to="/admin">`. |
| `{{ bgMediaEl }}` | `{bgMediaEl}` (it's a React node or null). |
| attributes `inputMode`, `maxLength`, `autoPlay`, `playsInline`, `crossorigin` | React camelCase: `inputMode`, `maxLength`, `autoPlay`, `playsInline`, `crossOrigin`. |

Notes:
- React needs `<>…</>` fragments when returning multiple siblings from a conditional/map.
- Numbers vs strings: prefer **string** values with units for safety. `zIndex` may be a number or string; both fine.
- Do not invent new styling. Do not "improve" the design.

## Imports available
- `import { useStore } from '../store.jsx';` — the single source of state + actions. (Path depends on file location: from `src/pages/` or `src/components/` or `src/admin/` it's `'../store.jsx'`; from `src/pages/themes/` it's `'../../store.jsx'`.)
- `import { Hover, FocusInput, Toggle } from '../components/ui.jsx';` (`Toggle({ on, onClick, label, hint })` is the admin pill switch, `role="switch"`)
- `import { FONT } from '../theme.js';` (only `FONT` is exported; inline literal hex/gradients like the prototype for colors).
- `import { ph } from '../util.js';` if you need placeholder images directly (usually the store already provides enriched `imgSrc`).

## Conventions
- Default export the component. Function components only.
- File-level and function-level comments in **Chinese**; UI text stays **English** (verbatim from prototype).
- Match the prototype's exact copy, spacing, colors, radii, shadows.
- Every `.map()` element needs a stable `key`.
